# GPT 텍스트 생성 원리 시각화

Vue 3와 Vite로 만든 한국어 수업용 웹앱입니다. 첫 화면은 학생이 예상하고 실험하며 확인하는 **따라하며 배우기**입니다. 기존 여섯 단계는 **내부 원리 살펴보기**에서 사용할 수 있습니다.

## 학생 로그인과 관리자 기록

`#login`은 학생 로그인, `#admin`은 관리자 화면입니다. 이름·학번·비밀번호로 본인 기록에 접근하며, 첫 참여는 교수자가 등록한 수강생 명단과 수업 참여 코드가 필요합니다. 관리자는 명단 등록, 미참여·진행·완료 현황, 학생별 활동 및 문항 응답, 최초·최근 정답, 실험·서술과 전체 이벤트를 확인하고 CSV 요약을 내려받습니다.

기록 기능은 **Node 서버와 영구 데이터베이스가 있는 수업용 주소**에서 동작합니다. GitHub Pages만 배포한 상태에서는 공개 체험으로 표시하며 로그인·기록 저장이 되는 것처럼 보여 주지 않습니다. Render용 Docker/영구 디스크 설정은 `render.yaml`, 배포·계정 설정·백업 안내는 [deploy/CLASSROOM.md](deploy/CLASSROOM.md)에 있습니다. 서버 생성 및 연결이 완료되어야 학생 기록을 수집할 수 있습니다.

## 안내형 학습

1. **먼저 예상:** 문맥을 읽고 다음 말을 고른 뒤, 예시 문장 빈도와 계산 근거를 확인합니다.
2. **문맥 비교:** 갈증/배고픔, 비/햇빛, 기쁨/걱정의 문맥을 바꾸어 후보 비중을 비교하고 이유를 고릅니다.
3. **확률 실험:** 온도(Temperature)의 뜻을 먼저 읽고, 물·주스·차의 같은 기준 확률을 저온·기준·고온에서 비교합니다. Temperature에 따른 확률 변화와 1회/20회 샘플링 결과를 비교합니다. 조건을 바꾸면 횟수를 초기화해 분포가 섞이지 않도록 합니다.
4. **한 조각씩 생성:** 학생의 예상과 별도로 확률에 따라 선택합니다. 선택한 조각을 문맥에 붙인 뒤 후보를 다시 계산하고 종료까지의 문맥·확률·선택 기록을 남깁니다.
5. **개념 연결 실험:** 같은 계산 모형에서 문맥·온도·FFN 중간 숫자 수를 하나씩 바꿉니다. 예상한 뒤 실행하고, 단계별 숫자 비교와 이유 선택 피드백을 확인합니다. 세 실험은 이유를 맞히면 완료되며, 처음 예상과 자유 서술도 활동 중 유지합니다.
6. **이해 확인:** 새로운 상황에 적용하는 여덟 문항, 오답별 피드백, 관련 활동 돌아가기, 자신의 말로 설명하기를 제공합니다. 글은 자동 채점하지 않습니다.

첫 네 활동의 확률은 준비된 작은 문장 집합에서 **전체 현재 문맥이 일치하는 예시들의 다음 조각 빈도**로 계산합니다. 실제 GPT 신경망이 아니며, 실제 GPT가 문장을 검색해 빈도를 센다는 뜻도 아닙니다. 데이터와 계산은 `src/guidedModel.js`에 있습니다. 심화의 ‘문장 예시’ 방식을 선택하면 같은 예시 집합을 후보 생성에 재사용합니다. 개념 연결 실험과 심화의 기본 ‘계산 연결 모형’은 실제 행렬 계산으로 출력 점수와 확률까지 구합니다. 실제 토큰보다 읽기 쉬운 단어 단위 조각을 사용합니다.

`#learn`은 안내형 학습, `#connections`는 개념 연결 실험, `#tokenize`·`#embedding`·`#attention`·`#ffn`·`#output`·`#test`는 해당 심화 화면으로 연결됩니다. 학생 로그인 시 안내형 활동 상태는 서버에 저장되어 새로고침·재로그인 후 복원됩니다. 공개 체험은 새로고침하면 초기화됩니다. 개념 연결 실험에서 심화로 이동할 때 문맥·온도·FFN 중간 차원도 함께 전달됩니다. 공개 체험은 기록을 저장하지 않습니다. 수업용 학습실에서는 학생에게 저장 항목을 안내하고 이름·학번·문항 응답·실험과 서술 기록을 저장합니다.

## 바로 실행하기

Node.js 24 이상이 필요합니다.

```bash
npm ci
npm run dev
```

기본 첫 화면의 **안내형 학습**은 API 키 없이 작동합니다. **심화 화면**의 기본값은 외부 AI 호출 없이 여섯 단계를 실제로 연결하는 **계산 연결 모형**입니다. 가중치는 학습하지 않은 고정 예시이고 출력 어휘는 6개로 제한됩니다. 자연스러운 문장 생성이나 질문 응답용 챗봇이 아닙니다. 기존 문장 예시 후보와 선택적 Gemini 후보 방식도 사용할 수 있습니다.

- **최종 출력:** FFN 숫자 → 후보별 출력 점수 → 온도 적용 → Softmax 확률의 표와 곱셈·덧셈 근거를 확인합니다. 예측 → Temperature 변경 → 문맥에 추가로 한 단계씩 생성합니다.
- **테스트:** 계산 연결 모형에서는 매 반복마다 전체 현재 문맥에서 FFN과 출력층까지 다시 계산한 분포로 선택합니다. 종료 토큰이 나오거나 10회 실험 한도에 도달하면 멈추며, 한도 도달을 모델의 종료 선택으로 표시하지 않습니다. 중지하거나 초기화할 수 있습니다.
- **임베딩:** 토큰 ID와 숫자 목록의 차이, 임베딩 표와 차원의 뜻을 설명합니다. 같은 토큰의 기본 임베딩은 같지만 문맥 처리 이후의 표현은 달라질 수 있음을 ‘배’ 예시로 연결합니다. ‘사과 사과 바나나’를 입력해 반복 토큰의 값도 비교할 수 있습니다.
- **피드포워드(FFN):** 토큰·벡터의 뜻과 Attention과의 역할 차이를 먼저 설명합니다. 중간 숫자 수를 바꾸며 입력·중간·출력의 계산 값을 비교하고, ReLU와 가중치 설명을 펼쳐 볼 수 있습니다.
- **어텐션(Attention):** 문맥을 참고하는 비중과 Q·K·V, Softmax, 미래 위치 차단의 뜻을 먼저 설명합니다. 토큰을 선택해 비중과 합산 결과를 비교하고, 첫 번째 출력 성분의 `V × 비중` 계산표를 펼쳐 볼 수 있습니다. 어텐션 비중과 다음 토큰 확률의 차이도 안내합니다.
- **초기화:** 진행 중 요청과 애니메이션을 취소하고 생성 결과를 지웁니다.

각 개념의 핵심 정의는 바로 표시하고, 상세 예시와 수식은 펼쳐보도록 배치했습니다.

## GitHub에 올리기

이 폴더 안의 파일을 저장소 루트에 올립니다. `transfer_package` 폴더 전체를 한 단계 아래에 중첩하지 마세요.

소스 파일, `package.json`, `package-lock.json`, `index.html`, `vite.config.js`, `server.mjs`, `geminiProxy.js`, `tests/`, `.github/workflows/pages.yml`, `.gitignore`, `.env.example`를 포함합니다. 실제 `.env`, `node_modules/`, 빌드 결과 `dist/`는 소스 저장소에 올리지 않습니다.

### GitHub Pages

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
2. `main` 브랜치에 코드를 올립니다. 브랜치 이름이 다르면 `.github/workflows/pages.yml`의 `branches`를 맞춥니다.
3. **Actions → Build and deploy GitHub Pages**가 성공하면 배포 URL을 엽니다.

워크플로는 테스트 → 빌드 → Pages 배포를 실행합니다. 이미 코드를 올린 후 Pages를 켰다면 해당 워크플로의 **Run workflow**로 다시 실행합니다. 상대경로 빌드로 `/저장소이름/` 아래에서도 JS와 CSS가 로드됩니다.

GitHub Pages에서는 **교육용 데모**를 제공합니다. Node 서버와 비밀 API 키가 필요한 Gemini 호출은 정적 Pages에서 실행할 수 없습니다. 설정 기준: [Vite 공식 배포 안내](https://vite.dev/guide/static-deploy).

## Gemini 후보 생성 사용하기

선택 기능이며 데모와 분리되어 있습니다. 모델이 작성한 후보와 추정 확률을 보여줍니다. 실제 GPT의 내부 토큰 확률을 조회하는 기능이 아닙니다.

`.env.example`을 `.env`로 복사한 후 **서버 환경에만** 키를 설정합니다.

```dotenv
GEMINI_API_KEY=실제_키
GEMINI_MODEL=gemini-2.5-flash-lite
VITE_ENABLE_GEMINI=true
```

개발 중에는 `npm run dev`를 실행하고 화면의 후보 생성 방식을 Gemini로 변경합니다. 빌드한 앱과 API를 함께 실행하려면:

```bash
npm run build
npm start
```

기본 주소는 `http://127.0.0.1:3000`입니다. 포트는 `PORT`, 수신 주소는 `HOST`로 지정합니다. 이 서버는 로컬 수업용 기본 구성입니다. 외부 공개 서버에 올릴 경우 운영 환경의 접근 제한과 API 사용량 제한을 적용하세요.

- `GEMINI_API_KEY`를 `VITE_`로 시작하는 변수에 넣지 마세요. `VITE_` 변수는 브라우저 코드에 포함됩니다.
- API 키 누락·실패·시간 초과는 화면에 표시합니다. 실패한 실제 호출을 데모 결과로 바꿔 표시하지 않습니다.
- 후보를 작성할 때의 Gemini Temperature는 고정하고, 수업용 Temperature는 클라이언트 확률에 한 번 적용합니다.
- Gemini 기능은 서버 설정과 모델 이용 가능 여부에 따라 작동합니다. 참고: [Gemini 모델](https://ai.google.dev/gemini-api/docs/models), [구조화된 출력](https://ai.google.dev/gemini-api/docs/structured-output).

## 교육용 계산의 범위

- 토큰 분할과 ID는 설명용 규칙·해시이며 실제 GPT 토크나이저가 아닙니다.
- 임베딩은 고정된 예시 값입니다. 같은 토큰은 같은 값을 가지며, Attention과 FFN에서는 첫 4개 성분을 사용합니다.
- Attention은 미래 토큰을 마스킹한 scaled dot-product와 Softmax로 계산합니다. 지도 색은 각 행 최댓값 대비 상대 강도이며, 막대는 실제 예시 계산 비중입니다.
- FFN은 위치마다 같은 고정 가중치로 행렬곱·ReLU·행렬곱을 수행합니다. 그림에는 은닉 노드를 최대 8개만 표시하지만 선택한 전체 차원을 계산합니다.
- 기본 계산 연결 모형의 출력층은 FFN의 4개 숫자를 고정 가중치와 편향으로 6개 후보 점수로 변환합니다. 점수를 온도로 나눈 뒤 Softmax를 적용합니다. ‘문장 예시’와 Gemini 방식은 별도 후보를 제공합니다.
- 실제 모델의 학습, 위치 정보, 다중 헤드, 잔차 연결, 정규화, 전체 어휘 출력층은 생략합니다.

계산식은 `math_logic.md`에 정리했습니다.

## 검증

```bash
npm test
npm run build
```

확률 정규화, 저온 샘플링 수치 안정성, 0 확률 제외, 인과 마스킹, FFN 차원 유지, 데모 종료, 요청 취소, 서버 응답, 안내형 문맥별 빈도 및 생성 분기의 일관성, 출력층의 실제 계산 근거, 온도의 적용 위치, 세 비교 실험의 변화 범위, 미래 정보 차단 및 다음 문맥 연결을 확인합니다. 브라우저 화면 검사와 실제 Gemini 응답은 이 검증에 포함되지 않습니다.
